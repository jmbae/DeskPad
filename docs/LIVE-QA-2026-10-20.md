# DeskPad 실제 Mac 연결 QA — 2026-10-20

## 검증 기준

검증 대상은 후속 [PR #5](https://github.com/nedpark/DeskPad/pull/5)와 [PR #6](https://github.com/nedpark/DeskPad/pull/6)를 통합한 로컬 `main`의 `845534a`다. 원격 `main`에는 PR을 병합하지 않았다. 이전 점검 내용은 [2026-10-19 통합 기록](READINESS-2026-10-19.md)에 보존한다.

Mandu Store iPad 시뮬레이터(iPadOS 26.5)에서 DeskPad를 실행해 실제 Mac 화면 공유 서버의 6016 × 3384 화면에 연결했다. 아래 결과는 시뮬레이터에서 확인한 것으로, 실물 iPad 검증을 대신하지 않는다. 저장된 연결의 Keychain 접근에는 ad-hoc 서명한 시뮬레이터 빌드를 사용했다. 재현 빌드 명령은 [TESTING.md](TESTING.md)에 있다.

## 남은 성능 문제

실제 6016 × 3384 화면의 Raw 프레임 수신에서 약 14~20초 지연이 남아 있다. 입력 패킷 전송과 화면 갱신은 별개이므로, 화면 변화가 늦게 보이는 현상을 곧바로 입력 미전송으로 판단하면 안 된다. 현재 입력 동작 확인과 별도로 고해상도 화면 전송 성능 개선이 필요하다.

## 오전 후속 검증

잠금 해제 후 재접속 성공 시 81,432,576바이트 첫 Raw 프레임 수신에 30.4초가 걸렸다. 앞선 두 차례 오류의 원인은 확정하지 않았으며 재접속 안정성 전체를 통과로 판단하지 않는다. 기본 macOS 화면 공유 클라이언트도 당시 검은 화면 이후 연결 목록으로 돌아왔다. 드래그 시험에서는 창 이동을 확인하지 못해 입력 시작 좌표와 최종 이동 패킷 경로를 추가 점검하고 있다.

드래그 시작점 복원과 버튼 해제 전 마지막 이동을 보완한 [PR #7](https://github.com/nedpark/DeskPad/pull/7)을 독립 리뷰 후 로컬 main `c17cbf6`에 통합했다. 기존 코드에서 실패한 회귀 테스트가 수정 후 통과했다. 최신 시뮬레이터 설치 및 원래 iOS 27 설정의 Release 빌드도 성공했다.

## TestFlight 준비

기존 로컬 배포 프로파일을 이용한 개발 서명 아카이브와 App Store 배포용 IPA export에 성공했다. 이 준비용 산출물은 드래그 수정 전 코드이며 업로드하지 않았다. App Store Connect의 기존 앱 식별자와 마지막 빌드 번호를 확인한 후 최종 코드를 다시 아카이브해야 한다. 실물 iPadOS 26을 지원하는 배포 빌드는 deployment target 26.0을 빌드 인자로 적용하며 저장소의 원래 설정을 임의로 바꾸지 않았다.

최신 수정 빌드에서도 재연결과 실제 데스크톱 표시를 추가로 확인했다. 이 환경에서는 6K 전체 Raw 프레임 수신에 약 25~30초가 걸리기도 했다. 시뮬레이터 `Command+Space`는 iPad 시스템 Spotlight에도 전달되어 원격 단축키 통과 근거로 사용하지 않았으며 테스트 오버레이는 닫았다.

## 대상 측 연결 종료 처리 — 1.1 (2)

## 화면 갱신·포인터 개선 — 1.1 (3)

[PR #9](https://github.com/nedpark/DeskPad/pull/9)의 로컬 포인터 표시와 [PR #10](https://github.com/nedpark/DeskPad/pull/10)의 ZRLE 압축 수신을 독립 리뷰 후 로컬 main `a05f6d0`에 통합했다. 원격 main에는 병합하지 않았다.

- ZRLE(encoding 16)를 우선 요청하며, 지원하지 않는 서버에는 Raw 경로를 유지한다. 세션마다 zlib 스트림을 유지하고 모든 ZRLE 타일 형식을 처리한다. 압축 길이·압축 해제 크기·타일 경계·팔레트 인덱스·시간 예산을 검사한다.
- Raw 픽셀 변환에서 채널별 Foundation Data 접근을 버퍼 접근으로 바꿨다. 동일한 6K 입력과 출력 검증을 사용한 최적화 벤치마크는 약 417ms → 15ms였다.
- 로컬 입력 위치를 고대비 링·십자로 표시하고 클릭 시 색상과 짧은 펄스를 표시한다. 포인터 레이어 이동은 원격 이미지 재렌더링을 요청하지 않는다. 확대·화면 이동·리사이즈 시 좌표를 유지하고 포커스 해제·세션 종료 시 정리한다. 이 표시는 요청한 입력 위치이며 서버가 입력 처리를 완료했다는 표시가 아니다.

### 실제 Mac 측정

동일한 실제 Mac의 6016 × 3384 화면에 Mandu Store iPad 시뮬레이터로 연결했다. 개선 후 측정은 `Debug` 빌드에 `SWIFT_OPTIMIZATION_LEVEL=-O`를 적용해 배포와 같은 최적화 수준을 사용하면서 DEBUG 시간 로그를 유지했다. 이전 Raw 기준 측정은 일반 Debug였다. 아래 네트워크 수신 시간과 별도의 최적화 픽셀 변환 벤치마크를 구분한다. 화면 내용과 네트워크 상태는 측정 사이 달라질 수 있으며 실물 iPad 결과는 아니다.

| 측정 | 이전 Raw | 개선 후 ZRLE |
| --- | ---: | ---: |
| 첫 전체 화면 전송량 | 81,432,576 bytes | 5,328,690 bytes |
| 첫 payload 수신 시간 | 24,096ms | 1,852ms |
| ZRLE 해제 | 해당 없음 | 64ms |
| 첫 업데이트 수신·해제·모델 반영 | 약 26.7초 (일반 Debug) | 1,923ms (최적화 빌드) |

실제 Mac이 encoding 16을 선택했다. 화면의 색상과 내용이 정상적으로 표시됐고, 포인터 링은 큰 화면 수신을 기다리지 않고 나타났다. 닫기 후 재접속에서도 새로운 ZRLE 스트림으로 첫 화면을 정상 표시했다(5,561,119 bytes, 수신 1,706ms, 수신·해제·복사 1,779ms).

10:24~10:26 KST 구간 두 세션에서 수집한 343개 업데이트의 처리 시간 중앙값은 9ms, 95백분위는 712ms, 최대는 2,082ms였다. 이는 업데이트 메시지의 수신·해제·모델 반영 시간이며 입력→실제 화면 표시 지연이나 FPS가 아니다. 큰 화면 변화와 네트워크 지연은 여전히 영향을 준다. 관측 구간에서 오류/원격 종료 상태는 없었다.

## 화질보다 지연 우선 — 1.1 (4)

사용자가 일부 화질 저하를 허용하면서 **Mac 기본 화면 공유만 사용**하도록 지정했다. [PR #11](https://github.com/nedpark/DeskPad/pull/11), [PR #12](https://github.com/nedpark/DeskPad/pull/12), [PR #13](https://github.com/nedpark/DeskPad/pull/13)을 로컬 main `9ba7c61`에 통합했다.

- 기본 `속도 우선`은 RGB565(16비트 색상) + ZRLE를 사용한다. `원본 색상`은 RGB888을 유지한다. 목록의 속도계 메뉴 또는 연결 화면의 `화면 보기`에서 선택하며, 선택은 저장되고 변경 시 재연결한다.
- 실제 Mac은 8bpp RGB332와 32bpp 컨테이너/depth8 RGB332 모두 픽셀 형식 전송 직후 TCP RST로 종료했다. 이 두 형식은 최종 선택지에 노출하지 않는다. RGB565와 RGB888은 실제 연결·화면 표시·전환을 확인했다.
- 전송 대기 중 연속 마우스 이동은 최신 위치로 병합한다. 버튼 누름·해제 위치, 휠, 키·클립보드 순서는 보존한다. 취소·재연결 시 이전 큐를 제거한다.
- 작은 입력 패킷의 Nagle 버퍼링을 끄도록 TCP noDelay를 설정했다. 이 플래그만의 지연 개선 수치는 따로 측정하지 않았다.
- 기존 로컬 포인터 표시를 유지한다. 별도 Mac 앱, 모니터 해상도 변경, Apple 전용 HEVC 미디어 경로는 추가하지 않았다.
