# DeskPad 실제 Mac 연결 QA — 2026-10-20

## 검증 기준

검증 대상은 후속 [PR #5](https://github.com/nedpark/DeskPad/pull/5)와 [PR #6](https://github.com/nedpark/DeskPad/pull/6)를 통합한 로컬 `main`의 `845534a`다. 원격 `main`에는 PR을 병합하지 않았다. 이전 점검 내용은 [2026-10-19 통합 기록](READINESS-2026-10-19.md)에 보존한다.

Mandu Store iPad 시뮬레이터(iPadOS 26.5)에서 DeskPad를 실행해 실제 Mac 화면 공유 서버의 6016 × 3384 화면에 연결했다. 아래 결과는 시뮬레이터에서 확인한 것으로, 실물 iPad 검증을 대신하지 않는다. 저장된 연결의 Keychain 접근에는 ad-hoc 서명한 시뮬레이터 빌드를 사용했다. 재현 빌드 명령은 [TESTING.md](TESTING.md)에 있다.

미확정·미검증 항목은 성공으로 판단하지 않는다. 드래그와 우클릭은 실물 입력 장치로 추가 확인해야 한다. 재접속 후 키보드 입력은 시뮬레이터 시스템 단축키가 개입하여 최종 확인하지 못했다.

## 자동 검증과 빌드

- UIKit 입력 테스트 20개 통과: XCTest 11개와 Swift Testing 9개 (드래그 후속 수정 포함).
- 실제 loopback TCP 세션 시나리오 13개 통과.
- 프로젝트의 원래 iOS 27 deployment 설정을 유지한 최신 Release 기기 빌드 `BUILD SUCCEEDED` 확인.
- Release 빌드 로그: `/tmp/deskpad-final-release.log`.
- 산출물: `build/DerivedData/Build/Products/Release-iphoneos/DeskPad.app`.

Release 기기 산출물은 unsigned 빌드이며, 실물 기기에 설치 가능한 서명 패키지나 TestFlight 배포물은 아니다.

## 남은 성능 문제

실제 6016 × 3384 화면의 Raw 프레임 수신에서 약 14~20초 지연이 남아 있다. 입력 패킷 전송과 화면 갱신은 별개이므로, 화면 변화가 늦게 보이는 현상을 곧바로 입력 미전송으로 판단하면 안 된다. 현재 입력 동작 확인과 별도로 고해상도 화면 전송 성능 개선이 필요하다.

## 오전 후속 검증

잠금 해제 후 재접속 성공 시 81,432,576바이트 첫 Raw 프레임 수신에 30.4초가 걸렸다. 앞선 두 차례 오류의 원인은 확정하지 않았으며 재접속 안정성 전체를 통과로 판단하지 않는다. 기본 macOS 화면 공유 클라이언트도 당시 검은 화면 이후 연결 목록으로 돌아왔다. 드래그 시험에서는 창 이동을 확인하지 못해 입력 시작 좌표와 최종 이동 패킷 경로를 추가 점검하고 있다.

드래그 시작점 복원과 버튼 해제 전 마지막 이동을 보완한 [PR #7](https://github.com/nedpark/DeskPad/pull/7)을 독립 리뷰 후 로컬 main `c17cbf6`에 통합했다. 기존 코드에서 실패한 회귀 테스트가 수정 후 통과했다. 최신 시뮬레이터 설치 및 원래 iOS 27 설정의 Release 빌드도 성공했다.

## TestFlight 준비

기존 로컬 배포 프로파일을 이용한 개발 서명 아카이브와 App Store 배포용 IPA export에 성공했다. 이 준비용 산출물은 드래그 수정 전 코드이며 업로드하지 않았다. App Store Connect의 기존 앱 식별자와 마지막 빌드 번호를 확인한 후 최종 코드를 다시 아카이브해야 한다. 실물 iPadOS 26을 지원하는 배포 빌드는 deployment target 26.0을 빌드 인자로 적용하며 저장소의 원래 설정을 임의로 바꾸지 않았다.

최신 수정 빌드에서도 재연결과 실제 데스크톱 표시를 추가로 확인했다. 이 환경에서는 6K 전체 Raw 프레임 수신에 약 25~30초가 걸리기도 했다. 시뮬레이터 `Command+Space`는 iPad 시스템 Spotlight에도 전달되어 원격 단축키 통과 근거로 사용하지 않았으며 테스트 오버레이는 닫았다.

## 대상 측 연결 종료 처리 — 1.1 (2)

[PR #8](https://github.com/nedpark/DeskPad/pull/8)을 로컬 main `28bcdab`에 통합했다. 화면 초기화 또는 연결 완료 후 서버 EOF/연결 오류를 받으면 별도 종료 상태로 전환하고, 화면·클립보드·입력 대기열을 정리한다. UI는 `Mac과의 연결이 종료되었습니다`와 공유 설정/네트워크 확인 안내, 수동 `다시 연결` 버튼을 표시한다. 종료 시 키보드도 명시적으로 닫는다. 프로토콜만으로 공유 중지와 네트워크 장애를 구별할 수 없으므로 특정 원인을 단정하지 않는다. 로컬 수신 시간 초과는 별도 오류로 유지한다.

검증:

- 전체 TCP 회귀 16개 통과. 신규 FIN, RST, 첫 Raw payload 중 종료 각각에서 화면/클립보드 초기화, 종료 후 입력 차단, 재연결과 새 입력 전달을 확인했다.
- 최종 quick 13개와 Release 빌드 통과. 독립 코드 리뷰 승인.
- ad-hoc 서명한 최신 시뮬레이터 빌드를 설치했다. 실제 사용 중인 Mac의 공유 설정은 변경하지 않고, loopback RFB 테스트 서버를 임시 연결로 등록해 검증했다.
- 서버에서 TCP 연결을 닫자 시뮬레이터의 원격 화면이 제거되고 종료 안내 및 `다시 연결` 버튼이 표시됐다. 버튼을 누르자 두 번째 세션에서 원격 화면이 다시 표시됐다. 임시 연결과 테스트 서버는 검증 후 정리했다.
- silent network blackhole처럼 종료 신호가 전혀 오지 않는 경우의 감지 시간을 검증한 것은 아니다.
